# Чтение с реплик

Запись идет с `writeConcern: "majority"`, но secondary может отставать. Чтение только что записанного документа идет на primary.

| Операция | Куда | Допустимый лаг |
| :- | :- | :- |
| Каталог `products` по категории и цене | `secondaryPreferred` | 5 с |
| Карточка товара | `secondaryPreferred` | 5 с |
| История заказов | `secondaryPreferred` | 5 с |
| Статус заказа по `{ user_id, _id }` | primary | нет |
| Повтор оформления, чтение заказа перед списанием | primary | нет |
| Активная корзина | primary | нет |
| Обе корзины при слиянии | primary | нет |

Каталог и карточка читаются часто, описание меняется редко. Устаревший остаток на витрине не продает товар: списание делает условный `$inc` на primary. История показывает прошлые заказы. Статус и повтор оформления читают primary, иначе покупатель видит старый статус, а повтор может списать остаток еще раз. Корзина меняется часто, и слияние с secondary потеряет только что добавленную позицию.

Для чтений с secondary хватает 5 секунд. Если лаг по `replSetGetStatus` больше, они уходят на primary. `maxStalenessSeconds` не ставится: минимум драйвера 90 секунд. При `secondaryPreferred` недоступные secondary не останавливают запрос, он выполняется на primary.

```javascript
db.products.find({ category: "electronics" }).readPref("secondaryPreferred")
db.orders.find({ user_id: "user-1", _id: "order-1" }).readPref("primary")
```
